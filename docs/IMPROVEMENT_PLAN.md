# 🚀 Orbit Merge — план улучшения игры

> Пошаговый план развития игры на основе [`docs/TEAM_REVIEW.md`](./TEAM_REVIEW.md)
> (ревью командой из 10 ролей). Этапы упорядочены **по зависимостям**: сначала то,
> что чинит/разблокирует всё остальное, затем глубина, удержание и деньги.
>
> Дата: 2026-06-26 · Базовая версия: прототип на GitHub Pages (HTML5 Canvas, один файл).

---

## Как устроен план

- **7 этапов** (Этап 0 … Этап 6), каждый — самостоятельная веха с понятным результатом.
- У каждой задачи: **приоритет** (P0/P1/P2), **сложность** (S/M/L), **роль-владелец**.
- **DoD** (Definition of Done) — критерий, по которому этап считается завершённым.
- **Метрика успеха** — что должно измениться (после Этапа 1, когда появится аналитика).
- **Зависимости** — что должно быть готово раньше.

### Логика последовательности

```
Этап 0  Стабилизация (2 Crit-бага)      ← без этого игра попросту сломана
   │
Этап 1  Измеримость (аналитика+CONFIG)   ← без данных нельзя оценивать всё дальнейшее
   │
Этап 2  Глубина и «джус» (combo и пр.)   ← делает игру по-настоящему хорошей
   │
Этап 3  Онбординг и UX                    ← превращает «хорошую» в «понятную всем»
   │
Этап 4  Retention / LiveOps               ← даёт причину возвращаться (главный риск)
   │
Этап 5  Монетизация                       ← деньги, но только на удержанной аудитории
   │
Этап 6  Перф и тех-долг + релиз-пакет     ← готовность к масштабу и сторам
```

> 💡 **Принцип:** не монетизировать и не лить трафик, пока не закрыт retention (Этап 4).
> Деньги на неудержанной аудитории = слив бюджета (см. вывод Producer + Monetization).

## 🔴 Этап 0 — Стабилизация (Hotfix) — ✅ ВЫПОЛНЕНО (2026-06-26)

> Все задачи закрыты и проверены в headless Chromium: при заблокированном
> `localStorage` игра запускается без ошибок; гейм-овер «Jar Overflow!» стабильно
> срабатывает при заполнении банки (~84 дропа в тесте). Детали — в `index.html`.

**Цель:** игра должна корректно работать и заканчиваться у всех пользователей.
**Почему первым:** QA подтвердил вживую (Chromium) два **критических** дефекта, которые ломают суть продукта. Всё остальное бессмысленно, пока они есть.
**Зависимости:** нет. **Оценка:** ~1–2 дня.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 0.1 | **Фикс краша `localStorage`** — обернуть весь доступ (чтение/запись best и sound) в `try/catch` + in-memory fallback. Сейчас в Safari Private / WebView мессенджеров игра не стартует вообще. | P0 | S | Engineer |
| 0.2 | **Фикс недостижимого гейм-овера** — усилить расталкивание в солвере (несколько проходов overlap / больше `SUBSTEPS` / накопление коррекции), чтобы стопка росла вверх, а не «утрамбовывалась». | P0 | M | Engineer |
| 0.3 | **Переписать `checkOverflow`** — засчитывать переполнение по факту нахождения осевшего орба выше `DEAD_LINE` (без жёсткого `vy<0.6`), сбалансировать инкремент/декремент `overflowTimer`. | P0 | S | Engineer |
| 0.4 | **Глобальный кап частиц** (≈250) и/или кап `count` в `burst` — защита FPS (QA: 40 мерджей → 1010 частиц). | P1 | S | Engineer |
| 0.5 | **`clampDropX(x, tier)`** — передавать тир явно (сейчас крупный орб клампится по радиусу тира 0 и лезет за стенку). | P1 | S | Engineer |

**DoD:** игра запускается при заблокированном Storage; партия гарантированно заканчивается при заполнении банки; на каскадах нет просадки FPS от лавины частиц. Прогон в headless Chromium подтверждает overflow-завершение.

## 📊 Этап 1 — Измеримость (аналитика + конфиг)

**Цель:** сделать игру измеримой и легко-балансируемой — без этого нельзя оценить эффект любого следующего этапа.
**Почему вторым:** Data Analyst ставит измеримости **2/10**. Все дальнейшие решения и A/B зависят от данных. Producer: «слепой полёт прекращаем немедленно».
**Зависимости:** Этап 0. **Оценка:** ~2–3 дня.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 1.1 | **Тонкий `track(name, props)`** + батч-очередь, отправка через `navigator.sendBeacon` на `game_over`/`visibilitychange`. | P0 | M | Data Analyst + Engineer |
| 1.2 | **Базовые события:** `game_start`, `orb_drop`, `merge{tier}`, `star_reached`, `game_over{score,max_tier,duration_sec}`, `retry`, `mute_toggle`. | P0 | M | Data Analyst |
| 1.3 | **Сессионный таймер** по wall-clock (`Date.now()`), счётчики `totalDrops`/`totalMerges`, `session_id`/`device_id` в localStorage. | P0 | S | Engineer |
| 1.4 | **Вынести баланс в единый `CONFIG`** (грав, REST, cooldown, пороги overflow, `SPAWN_MAX`, веса спавна, размеры `TIERS[].r`) — фундамент под A/B и LiveOps remote-config. | P0 | M | Engineer |
| 1.5 | **Дашборды:** FTUE-воронка, D1/D7 по когортам, распределения `max_tier`/`duration`/`merges per session`. | P1 | M | Data Analyst |

**DoD:** каждое ключевое действие шлёт событие; есть дашборд с D1/FTUE/session length; весь баланс игры меняется из одного объекта `CONFIG`.
**Метрика успеха:** появились первые цифры — фиксируем **baseline** (D1, session length, % до Star, FTUE-проход) для сравнения дальше.

## ✨ Этап 2 — Глубина и «джус»

**Цель:** превратить «приятный прототип» в по-настоящему затягивающую игру (skill-ceiling + дофамин).
**Почему сейчас:** Game Designer/Artist/Sound единогласно: ядро сильное, но плоское — нет комбо, плоская сложность, тиры плохо читаются. Это дёшево и сильно повышает качество.
**Зависимости:** Этап 1 (мерить эффект). **Оценка:** ~3–5 дней.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 2.1 | **Combo-множитель за цепные слияния** — счётчик каскада за дроп, x2/x3…, popup «COMBO xN», бонус к очкам. | P0 | S | Game Designer |
| 2.2 | **Читаемость тиров** — пипы/цифра/значок внутри орба (не только цвет). Решает и **дальтонизм**. | P0 | S | Artist + UX |
| 2.3 | **Прогрессивная сложность** — со временем/счётом смещать веса `randSpawnTier` к старшим тирам (через `CONFIG`). | P0 | S | Game Designer |
| 2.4 | **Музыкальный звук** — квантизация тиров в гамму (`base*2^(scale/12)`), комбо-«лесенка» по высоте, `actx.resume()` после фона, Star-стингер. | P1 | S | Sound |
| 2.5 | **Merge-флэш + шоквейв-кольцо + additive-частицы** (`globalCompositeOperation='lighter'`, streak'и). | P1 | S | Artist |
| 2.6 | **Нелинейный шаг размеров тиров** (`r = base*1.18^tier`) — силуэты соседей расходятся. | P1 | S | Artist |
| 2.7 | **Star-celebration по-настоящему** (фуллскрин flash, лучи, slow-mo, золотой дождь, аккорд). | P2 | M | Artist + Sound |
| 2.8 | **1–2 спецшара** (Bomb / Rainbow) — тактика и вариативность. | P2 | M | Game Designer |

**DoD:** цепные слияния дают видимый/слышимый combo-фидбек; уровень орба читается без угадывания; сложность нарастает в течение партии.
**Метрика успеха:** ↑ session length, ↑ merges/session, ↑ % сессий с ≥1 chain, ↑ retry-rate.

## 📱 Этап 3 — Онбординг и UX

**Цель:** чтобы новичок понял игру за 5 секунд и ему было удобно на телефоне.
**Почему сейчас:** UX 5/10 — стена текста вместо туториала, эргономика большого пальца, accessibility. Прямо влияет на FTUE → D1.
**Зависимости:** Этап 2 (туториал должен показывать финальную механику с combo). **Оценка:** ~3–4 дня.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 3.1 | **Интерактивный туториал-«рука»** (3 шага: двигай → отпусти → смержи), блокирует UI до первого успешного слияния. | P0 | M | UX + Game Designer |
| 3.2 | **Маркер точки падения на полу** (виден из-под пальца) + усиленный «луч» прицела. | P0 | S | UX |
| 3.3 | **Pause + Restart в HUD** (сейчас паузы нет, рестарт только из Game Over). | P1 | S | UX |
| 3.4 | **Accessibility:** контраст `.muted` ≥4.5:1, базовый текст 12–14px, тач-таргеты ≥44px. | P1 | S | UX |
| 3.5 | **NEXT из угла канваса в HUD** рядом со Score, крупнее. | P1 | S | UX |
| 3.6 | **Предупреждение о переполнении** (затемнение + хаптик/звук) до фактического Game Over. | P2 | S | UX + Sound |
| 3.7 | **Снап к валидной позиции у края** + хаптик на дроп. | P2 | M | UX |

**DoD:** новый игрок без подсказок делает первое слияние; есть пауза и рестарт; интерфейс проходит базовый чек контраста/размеров; туториал-воронка трекается.
**Метрика успеха:** ↑ FTUE-проход (первый merge >80%, round2 >55%), ↑ D1.

## 🗓️ Этап 4 — Retention / LiveOps

**Цель:** дать причину возвращаться завтра. **Это главный риск проекта.**
**Почему сейчас:** LiveOps 3/10, Producer: «структурный риск D1/D7, его нельзя допилить полишем — надо проектировать». Закрываем до монетизации.
**Зависимости:** Этап 1 (профиль/CONFIG), Этап 3 (удержанный новичок). **Оценка:** ~1–1.5 недели.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 4.1 | **Profile-объект в localStorage** (`lastPlayed`, `streak`, `freezeTokens`, `dailyDone`, `totalScore`). | P0 | S | LiveOps + Engineer |
| 4.2 | **Seeded RNG (seed дня)** — заменить `Math.random()` в спавне на PRNG от сида дня (один порядок шаров для всех → честное соревнование). | P0 | S | LiveOps + Engineer |
| 4.3 | **Daily Challenge** — оверлей с целью дня + одна рейтинговая попытка по seed дня + свободные тренировки. | P0 | M | LiveOps + Game Designer |
| 4.4 | **Streak-календарь** + награды за серии 3/7 дней (freeze-токен против обнуления). | P0 | M | LiveOps |
| 4.5 | **Ачивки «собери все тиры»** (от `highestTier`) + экран коллекции. | P1 | M | LiveOps |
| 4.6 | **Уровни аккаунта** (XP за сессию) → разблокировка **скинов** (альт-палитры `TIERS`, без доната). | P1 | M | LiveOps + Artist |
| 4.7 | **Локальный недельный лидерборд** (best за день/неделю). | P1 | S | LiveOps |
| 4.8 | **Weekly-режимы** (Зен — откл. overflow; Спринт — таймер; Малый кувшин — узкое поле). | P1 | M | Game Designer |
| 4.9 | **Шеринг результата картинкой** (`canvas.toDataURL()` + score/seed) — виральность. | P2 | M | LiveOps + Artist |
| 4.10 | **Глобальный лидерборд** (бэкенд + аккаунты, честный по seed дня). | P2 | L | Engineer + LiveOps |

**DoD:** есть ежедневная цель и streak; игра помнит профиль; разблокируются скины за игру; работает локальный лидерборд.
**Метрика успеха:** ↑ D1 → 30%+, ↑ D7 → 10%+, ↑ sessions/DAU. **Гейт перехода к Этапу 5:** D1 ≥ ~25–30%.

## 💰 Этап 5 — Монетизация

**Цель:** заработок без вреда удержанию (rewarded-first).
**Почему сейчас:** Monetization 7.5/10 — жанр «денежный», но монетизировать имеет смысл только удержанную аудиторию (после Этапа 4).
**Зависимости:** Этап 4 (retention закрыт), Этап 1 (аналитика для экономики). **Оценка:** ~1 неделя.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 5.1 | **Ad-медиатор** (AdMob/AppLovin MAX) + события `ad_request/fill/show/reward`. | P0 | M | Monetization + Engineer |
| 5.2 | **Rewarded: Revive** после переполнения (убрать N верхних орбов, лимит 1/партию). | P0 | M | Monetization + Game Designer |
| 5.3 | **Rewarded: ×2 очков** на гейм-овере (до записи best). | P0 | S | Monetization |
| 5.4 | **Remove Ads (IAP)** + «No-Ads пробник» (первые 2–3 партии без интеров). | P0 | M | Monetization |
| 5.5 | **Interstitial только на гейм-овере** с частотным капом (A/B по частоте). | P1 | S | Monetization |
| 5.6 | **Бустеры** (Бомба — удалить орб; Реролл next) — rewarded / валюта, лимит на партию. | P1 | M | Monetization + Game Designer |
| 5.7 | **Косметика-IAP** (скины/фоны/трейлы/звук-темы) — без pay-to-win. | P1 | M | Monetization + Artist |
| 5.8 | **Софт-валюта + паки** + daily reward. | P2 | M | Monetization |

**DoD:** rewarded-петли (revive, ×2) работают; есть Remove Ads; интеры под капом и off на онбординге; экономика трекается.
**Метрика успеха:** ↑ ARPDAU при стабильных D1/D7 (контроль, что монетизация не уронила retention).
**Анти-паттерны (НЕ делать):** интеры в середине партии, pay-to-win, тёмные паттерны, принудительный rewarded, гейт best-результата за деньги, бесконечные ревайвы.

## ⚙️ Этап 6 — Перформанс, тех-долг и релиз-пакет

**Цель:** держать 60 FPS на бюджетных устройствах и подготовить выход в сторы.
**Почему последним:** оптимизация важна, но не блокирует валидацию петли; делаем перед масштабированием трафика. Часть перф-задач можно подтянуть раньше, если дашборд покажет просадки FPS.
**Зависимости:** параллельно с Этапами 4–5; релиз-пакет — в конце. **Оценка:** ~1 неделя.

| # | Задача | Приоритет | Сложн. | Роль |
|:--:|---|:--:|:--:|---|
| 6.1 | **Кеш спрайтов орбов** в offscreen-canvas по тиру; `drawImage` вместо `createRadialGradient`+`shadowBlur` каждый кадр. | P1 | M | Engineer |
| 6.2 | **Отложенный merge** (`pendingMerges` после цикла) — убирает мутацию `orbs` во время итерации и чинит каскады. | P1 | M | Engineer |
| 6.3 | **`Math.hypot` → сравнение квадратов**; пропускать `o.dead` в цикле стен/интеграции. | P1 | S | Engineer |
| 6.4 | **Пул объектов** для частиц + swap-remove вместо `filter`/`some` каждый кадр. | P1 | M | Engineer |
| 6.5 | **Брод-фаза коллизий** (spatial hash / grid) — снять O(n²) при полной банке. | P2 | L | Engineer |
| 6.6 | **Реализовать `sleeping`** (усыплять медленные орбы) — убрать jitter у дна. | P2 | M | Engineer |
| 6.7 | **Сохранение состояния партии** (resume после сворачивания) + debounce resize/orientation. | P1 | M | Engineer |
| 6.8 | **Pointer Events** вместо отдельных mouse/touch — убрать рассинхрон при двух указателях. | P2 | M | Engineer |
| 6.9 | **Релиз-пакет:** store-иконка + 5 скриншотов + ASO + privacy policy; опц. PWA-манифест / нативная обёртка (Capacitor). | P1 | M | Artist + Producer |

**DoD:** стабильные 60 FPS при полной банке на low-end Android; партия восстанавливается после сворачивания; есть store-обвязка / PWA.
**Метрика успеха:** нет жалоб на FPS/фризы; ↓ crash-rate; готовность к публикации.

## ✅ Что делать прямо сейчас (ближайший спринт)

Минимальный набор, дающий максимум эффекта на единицу усилий:

1. **Этап 0 целиком** — 2 критических бага (без этого игра «сломана»).
2. **Этап 1.1–1.4** — аналитика + `CONFIG` (разблокирует все решения).
3. **Этап 2.1–2.3** — combo, читаемость тиров, прогрессивная сложность (дёшево, сильно поднимает качество).

> Эти три блока — короткие, измеримые и сразу заметны игроку. После них появятся первые
> цифры, по которым приоритизируем остальное.
